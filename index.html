Project Overview

Loop Together explores how a browser-based audio instrument can make sound creation approachable for beginners. Users experiment with microphone input, short recordings and repeating sounds through simple controls.

These six parallel prototypes explore two design areas: looping and sampling interaction, and feedback. Each group contains three alternatives that investigate different ways of helping users understand and explore sound.

Area 1 — Looping and Sampling Interaction

This area explores how users record a sample and control its repetition. It directly connects to my extended technique of looping and sampling. The three versions use buttons, circular movement and selectable steps to represent and control repetition.

My aim is to let beginners experiment with rhythm without needing to read musical notation. Each prototype offers a different way to connect an action with a repeating sound.

PROTOTYPE 1A

Button Loop

Users record a short sound and repeat it using familiar recording and playback buttons. The complete sample repeats, so the recording length determines the length of the loop.

This design explores a simple starting point for beginners. Clear action labels allow users to focus on recording and listening before arranging a rhythm.

Open Prototype 1A

PROTOTYPE 1B

Circular Loop

This version represents an eight-beat cycle as a circle. A highlighted position moves around the display, and the recorded sample restarts at the beginning of each cycle.

The circular layout presents repetition as a return to a starting point. It explores whether visible movement helps users follow the cycle and anticipate when their sound will restart.

Open Prototype 1B

PROTOTYPE 1C

Step Loop

Users select positions in an eight-step grid to choose when a recorded sample plays. Green squares indicate selected steps, while an outline shows the current position in the sequence.

This version gives users control over the placement of sound within a repeating pattern. It explores rhythm-making through simple on-and-off choices.

Area 2 — Feedback and Guidance

This area explores how the interface communicates sound activity and system states. Beginners need to understand whether the microphone is receiving sound, what the system is doing and which action they can take next.

The three versions emphasise a live level display, written instructions and expressive animation. They explore feedback as confirmation, guidance and encouragement to experiment.

PROTOTYPE 2A

Visual Feedback

A live meter and pulsing circle respond to microphone activity. Changes in bar length and circle size provide a visible response to speaking, tapping or clapping.

This design explores how simple visual changes can confirm that sound is being received. The display represents relative activity rather than a calibrated sound measurement.

Open Prototype 2A

PROTOTYPE 2B

Text Feedback

Short instructions guide users through recording, stopping and playing a sample. The message changes to explain the current state and the next action.

This design explores explicit guidance for first-time users. Disabled buttons support the instructions by indicating which actions are currently available.

Open Prototype 2B

PROTOTYPE 2C

Expressive Feedback

Animated bars respond to frequency information from the microphone. Different sounds create changing patterns across the display.

This version explores how animation can encourage sound experimentation. Users can try their voice, a clap or a tap and observe the visual response. Its focus is live visual feedback rather than playback.

Open Prototype 2C

Shared Design Choices

The prototypes use a dark background, green controls and clear labels. Keeping the visual style consistent helps draw attention to the interaction differences between versions.

Status messages explain recording and playback states. Selected steps and playback positions use different visual treatments to help users follow their actions.

Peer User Testing

The testing session will explore how participants understand each prototype, what they expect to happen and where they need more guidance.

Testing Tasks

  1. In 1A, record a short sound, start the loop and stop it.
  2. In 1B, record a sound and follow one complete circular cycle.
  3. In 1C, activate three steps, play the sequence and change one selected step.
  4. In 2A, start the microphone and compare a quiet sound with a louder sound.
  5. In 2B, follow the instructions to record and play a sample.
  6. In 2C, try a voice sound, a clap and a tap. Observe how the bars change.

Discussion Prompts

  • Which actions were clear, and which were confusing?
  • What did you expect each visual change to mean?
  • Which loop interaction would you choose, and why?
  • Which feedback elements helped you understand the system?
  • What would you change to improve the experience?
